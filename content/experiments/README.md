# 실험
<!-- source: wiki/experiments/README.md -->

한 페이지에 재현 가능한 레시피 하나: 목적, 환경(`ACWW_*` 변수, 오라클
명령), 프레임을 명시한 예상 관측, 그 관측을 만들어 낸 실행, 그리고 반증 조건.

각 페이지는 **실행됨** -- 그 숫자가 나온 실행 디렉터리를 명시한다 -- 이거나 **설계만 됨
(아직 미실행)** 이며, 후자의 경우 미래의 실행이 사용할 정확한 환경과 명령을 담고
있고, 예측은 확인되기 위해서가 아니라 반증 가능하도록 쓰여 있다.

## 실행됨

| 페이지 | 무엇을 확립하는가 |
|---|---|
| `off-recipe.md` | 대조 실행: 스타일러스를 끈 채 프레임 9,000까지의 스크린샷 31장을 SHA-256으로 비교한다 |
| `two-tap-town-recipe.md` | 타이틀 화면에서 마을 회관까지 48,000 프레임의 게임 진행과, 그 구간에 대한 오라클 비교 |
| `gameplay-walkthrough.md` | 마을 회관 그 다음: 건물 밖으로 나가기, 마을 걷기, 지도, 주머니, 밤, 세이브 메뉴 -- 패드 스크립트를 가진 스냅샷에서부터 |
| `touch-calibration.md` | 원본에서 ROM 자체의 터치 포인트가 무엇을 담는가: 221,181 입력, 222,182 출력, 1~2 프레임 지연 |
| `touch-latency.md` | 접촉이 게임에 도달하기까지 몇 프레임이 걸리는가, 그리고 ARM7의 샘플이 왜 ROM의 VBlank 핸들러 뒤에 놓여야 하는가 |
| `savestate-resume.md` | 프레임 N에서 실행을 스냅샷하고 거기서 정확히 재개하여, 10분의 재생을 1분으로 줄인다 |
| `save-and-reload.md` | 플레이한(PLAYED) 게임이 영속되는가: 마을 실행 전체의 카드 요청 센서스, 게임이 쓰는 것, 그리고 저장된 마을로 부팅하는 두 번째 실행 |
| `live-play.md` | 키보드로 포트를 조작하기: `play.py`, 59.8261 Hz 페이서, 키 맵, 스타일러스 홀드 -- 그리고 스크립트된 실행이 하나도 움직이지 않았다는 영수증 |
| `run-stability.md` | 이 이미지에서 종료 코드가 뜻하는 것, 종료 코드 1이 왜 항상 외부 kill인가, 그리고 48,000 프레임 실행의 비용 |

## 모든 실험에 적용되는 규칙

- **대조 실행을 먼저 한다 (M15).** OFF 조건 없는 ON 조건은 아무것도 측정하지 못한다.
- **`ACWW_KEYS_AT` / `_FOR` / `_EVERY` 가 키 이름이다 (B1).** 짧은 형태는 읽히지 않으며
  실행을 조용히 DEMO 사이클로 바꿔 버린다.
- **어느 경로인지, 어느 런처인지, 어느 아티팩트인지, 어느 종료점인지 말한다 (B1, B8, B32, B38).**
  영수증(receipt)이 있는 실행과 직접 `acww.exe` 진단 실행은 서로 다른 주장이다.
- **프레임 수나 벽시계 시간으로 판단하지 않는다 (B12).** 종료점, 정확한 실패 정체,
  그리고 이미지로 판단한다.
- **측정을 먼저 의심한다 (M1).** 이 프로젝트의 도구 네 개가 맞기 전에 틀렸었다.
- 포트는 도구이지 진실이 아니다: 포트만의 관측은 등급 E이며, 오라클이 동의하거나
  소스가 설명하기 전까지 E에 머무른다.
- **2026-09-09 이전에 찍힌 실행과 비교할 때는 시계를 동결한다.** 포트의 RTC는 이제
  전진하며, 분(minute)이 낮/밤 블렌드를 구동하므로 모든 프레임이 달라진다;
  `ACWW_RTC_FREEZE=1`을 설정한다 [E: `../systems/time-and-rtc.md`].
- **종료 코드 1은 다른 누군가의 `taskkill`이지 실패가 아니다.** 이미지 안의 어떤 것도
  1로 종료하지 않는다 [E: `run-stability.md`].
